allowit paysh reconciles retained operations from a legacy AllowIt policy.

Use the original retained scoped capability and backend for that policy.
These commands do not create a policy, issue authority or start a new operation.
This command holds no signing key and never reads one.

Configuration (environment only):
  ALLOWIT_URL          service origin, e.g. https://allowit.example
                       (http is allowed only for localhost)
  ALLOWIT_PAYSH_TOKEN  the policy's scoped capability (call and status)
  ALLOWIT_CA_FILE      optional extra PEM root certificates

Commands:
  allowit paysh services [--json]
                 list the PaySH catalog, or this server's cooperating-v1
                 services in test-token units; no token needed
  allowit paysh call POLICY OPERATION_ID SERVICE_ID INPUT_JSON [--json]
                 reconcile an existing OPERATION_ID with its original input
  allowit paysh status POLICY OPERATION_ID [--json]
                 read, and advance, an earlier call

OPERATION_ID is chosen by the agent: 1 to 128 characters from A-Z a-z 0-9 _ -.
Use the original OPERATION_ID. Never retry a call with a new OPERATION_ID:
an unknown result may still have paid. Check it with status, or
rerun the identical call with the same OPERATION_ID. INPUT_JSON is limited to
4096 bytes. Each request is sent once; nothing is retried automatically.

awaiting_input means wait for, or ask, the owner to answer in AllowIt Requests.
Do not generate a replacement operation. owner_approved records a signed Yes
for the bounded original request; it is not payment or API delivery. Continue
explicitly with status, or rerun the identical call with the same OPERATION_ID
and original input. The CLI never answers for the owner or continues automatically.

Exit codes: 0 delivered (the API response received), 2 usage,
3 config or auth, 4 rejected request, 5 unknown result (keep the OPERATION_ID
and check status) or status unknown/settlement_unknown (operation unresolved;
payment may have been sent, never pay again for it), 12 pending (owner answer, payment or delivery not complete; check
status), 20 failed, denied or expired (no delivery). Expiry is not an owner denial. No HTTP error from call, including
401, 404 and 429, proves that nothing was paid; it exits 5 with the original
OPERATION_ID. JSON output includes paymentFinalized, derived from a pay receipt
with a signature and a finalized slot. A failed, denied or expired operation with any receipt
other than a swap, or an expired operation with a signature that has no receipt, stays
unknown (exit 5).
